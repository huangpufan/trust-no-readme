## Executive Verdict (总论)

逐行核查 `browser-use` 全部 146 个文件、双仓库合计 12,098 条 Git 提交、PyPI 拆包以及 21 组断网零凭据沙箱抓包后，呈现出非常鲜明的反差：**它的基础工程卫生做得并不差**（冷启动设 `ANONYMIZED_TELEMETRY=false` 对主库确实静默、零读取 `~/.codex`/`~/.ssh` 等外部凭据、CI 全锁 40 位 SHA、PyPI OIDC 发包、高危历史漏洞 `GHSA-x39x-9qw5-ghrf` 已修补）。

恰恰因为团队完全具备写干净代码的能力（同一版本的本地录屏模块甚至专门给密码框打星号），**下面五组与文档承诺背道而驰的遥测与边界设计，才明显不是偶发疏忽，而是连续的产品取舍**：

1. **持续 141 天默认上传原始脚本、终端输出与明文密码（F1）：** 硬锁依赖 `browser-harness==0.1.13` 绕过自身过滤表上传原始内容；联合创始人 `MagMueller` 未合并关闭修复 PR `#733` 后 4 小时 27 分照常发包；一位处理客户财务记账的用户（`#1053`）全靠 Windows 弹窗 Bug（`#6474`）才惊觉中招；`browser-use 1.0.8` 与主分支至今仍锁死在 `0.1.13`。
2. **11 月 9 日三小时连环删文档与扩上报（F2）：** 删掉 113 行 `TELEMETRY.md` → 2 小时 54 分后扩大 `agent_event` 默认上报（内网域名、完整路径、500 字结果、2,100 字 AI 评语、50 个自定义工具名 + 7 天磁盘队列）→ 46 秒后把 `README.md` 遥测整节删光，致 `1.0.0`–`1.0.5` 连续 6 天零说明。
3. **往 8 款编程 Agent 塞提示词绕过用户关闭的开关，6 天后变本加厉（F3）：** 随包 `SKILL.md` 指示 Claude Code/Codex/Cursor 每次跑完主动发反馈、不要求问用户；`cli.py` 写死 `consent=True`（沙箱全关照发 994 字节）；社区抗议 `#6467` 6 天后，`browser-harness#1068` 连最后一道隐藏拦截 `BU_MODEL_CODE` 也删掉，并在 Risk 栏明写 *“A model can call feedback without the user asking”*。
4. **连敲 `--help` / `--version` 也建永久 ID、开人物画像、扫 12 款 AI 工具并藏提示（F4）：** `browser-use` CLI 放行 `$process_person_profile: true`，连本地看帮助和版本号也触发，同时设 `notice=False` 关提示并在 `--help` 里不列 `telemetry` 子命令。
5. **关闭开关的多重暗坑与激进开发机默认边界（F5、F6）：** 运行时关闭在 `_at_exit()` 漏检 `job.consent` 照发（抓包自带 `enabled_at_build: false`）、常驻服务永久缓存 `telemetry.json`、跨包环境变量解析打架；默认宿主机免审 Python、MCP 进程内全环境变量 `exec()` 留永久未脱敏临时文件、`HEAD` PR `#6526` 自动切入个人 Chrome 并暴露 `use_my_chrome()`、云端默认向 `stderr` 打印免鉴权接管链接。
