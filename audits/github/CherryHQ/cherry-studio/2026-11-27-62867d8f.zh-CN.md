## Executive Verdict (总论)

逐项核查 Cherry Studio 全部 14,056 个仓库文件、10,844 条 Git 提交、官方 `v2.2.3` 安装包（`app.asar`）及 `bwrap --unshare-all` 断网抓包后，先交代核查无问题的部分：主进程 Sentry 关闭了 PII 且受隐私同意门控；关闭 `app.dist.auto_update.enabled` 确实能停掉定时更新检查；删除外部文件前界面明确提示保留原件；外部协议链接安装 MCP 时正确初始化为 `isTrusted: false` 并要求单独确认。

但在已发布的 `v2.2.3` 安装包与当前主线 `62867d8f` 中，共有四项公开的代码与承诺冲突（外加一处私密披露的 Windows 更新签名校验隐患）：

1. **国内版单独传原始 `accountId` 并发往美国 PostHog 开启人物画像，与“完全匿名、不画像”承诺冲突（F1）：** 同一份安装包代码里，国际版发送匿名 UUID 并关闭画像（`$process_person_profile: false`），唯独国内版（`edition === 'cn'`）把原始 `status.accountId` 拼进 `distinctId` 并设 `processPersonProfile: true` 发往 `https://us.i.posthog.com`，且引导页默认提前勾好同意框。正式版 `v2.2.3` 随包自带的仍是 `2026-08-20` 旧政策；昨天（`2026-11-26`）未发布主线的 PR `#25454` 只补改了随包 HTML，官网政策和设置页开关文案（“匿名发送错误报告和数据统计”）至今未改。
2. **持续 431 天零点击把聊天里的 `plantuml` 图源发给第三方，违背“绝不传输对话数据”承诺（F2）：** 聊天消息只要包含 `plantuml` 代码块，前端渲染时无需点击就会默认切到远程预览，压缩整段图源发往写死的 `https://www.plantuml.com/plantuml`（断网沙箱抓包反向解码 149 字节与原图完全一致）。
3. **关掉隐私收集开关后，更新检查仍带持久化 `Client-Id`，启动还会查未披露的第三方 IP 定位（F3）：** 关闭隐私收集后，只要没一并关闭自动更新，`AppUpdaterService` 仍持续发送持久化 `Client-Id`（`app.user.id`）；打包版启动时还会无条件请求未在隐私政策中披露的 `api.ipinfo.io`（硬编码 token）与回退 `api.internetdata.io`。
4. **手动导入 MCP 点普通“确认”即写入 `isTrusted: true` 并立即连接（F4）：** 手动导入 JSON/MCPB/DXT 时点击普通“确认”按钮，代码直接授信、启用并触发 `mcp.server.refresh_tools` 连接，界面未提示授信后果。

### F2: 持续 431 天零点击把聊天 `plantuml` 代码块完整图源发往 `www.plantuml.com`

**评级：** `H3 / R2` · **证据：** `E3+D` · **默认触发：** 是（聊天出现任意 `plantuml` 代码块） · **披露：** `public` · **关联承诺：** C3

- **实际代码行为：** [`src/renderer/components/chat/messages/markdown/CodeBlock.tsx:64-67,112-121`](https://github.com/CherryHQ/cherry-studio/blob/62867d8f0047919e37a1cd05315057d5cfcec09e/src/renderer/components/chat/messages/markdown/CodeBlock.tsx#L64-L67) 与 [`src/renderer/components/CodeBlockView/CodeBlockView.tsx:128-143,412-456`](https://github.com/CherryHQ/cherry-studio/blob/62867d8f0047919e37a1cd05315057d5cfcec09e/src/renderer/components/CodeBlockView/CodeBlockView.tsx#L128-L143) 将 PlantUML 注册为特殊预览视图并在渲染时默认激活。随后 [`src/renderer/components/Preview/PlantUmlPreview.tsx:14,70-92`](https://github.com/CherryHQ/cherry-studio/blob/62867d8f0047919e37a1cd05315057d5cfcec09e/src/renderer/components/Preview/PlantUmlPreview.tsx#L70-L92) 用 `pako.deflateRaw` 压缩整段图源，拼进写死的 `https://www.plantuml.com/plantuml` 直接 `fetch`，无弹窗确认、无关闭开关、也不能配置自定义服务器。

**关键源码（[`src/renderer/components/Preview/PlantUmlPreview.tsx:70-92`](https://github.com/CherryHQ/cherry-studio/blob/62867d8f0047919e37a1cd05315057d5cfcec09e/src/renderer/components/Preview/PlantUmlPreview.tsx#L70-L92)）：**

```ts
function encodeDiagram(diagram: string): string {
  const utf8text = new TextEncoder().encode(diagram)
  const compressed = pako.deflateRaw(utf8text)
  return encode64(compressed)
}

function getPlantUMLImageUrl(format: 'png' | 'svg', diagram: string, isDark?: boolean) {
  const encodedDiagram = encodeDiagram(diagram)
  if (isDark) {
    return `${PlantUMLServer}/d${format}/${encodedDiagram}`
  }
  return `${PlantUMLServer}/${format}/${encodedDiagram}`
}
```

- **实测验证与精确边界：**
  - **已观察结果：** 在官方 `v2.2.3` `app.asar`（`out/renderer/assets/PlantUmlPreview-RsIXcvSS.js`）确认原样存在。在 `bwrap --unshare-all` 断网沙箱直接运行该打包产物，截获 `GET https://www.plantuml.com/plantuml/svg/<encoded>` 并独立反向解码，完整还原 **149 字节**测试架构图，一字不差。
  - **不受影响范围：** 仅当消息含 `plantuml` 代码块时触发；React 自动激活预览由源码静态证明（`E3`），编码序列化与网络出站由沙箱抓包动态证明（`D`）。
- **时间线：**
  - `2025-02-18`（[`d0ee7647`](https://github.com/CherryHQ/cherry-studio/commit/d0ee764732)）：引入在线 PlantUML 渲染。

  - `2025-09-22`（[`cc650b58`](https://github.com/CherryHQ/cherry-studio/commit/cc650b58d3)）：官网隐私政策明确承诺不传输对话数据，截至 `2026-11-27` 冲突已持续 431 天。
